# История изменений

Здесь перечисляются заметные изменения MIRA-TV по версиям.

## 1.0.3 — 29 августа 2026

Исправление резервной копии при обновлении, запущенном через однострочный установщик.

### Исправлено

- обновление больше не пытается сохранять временный `/dev/fd/...` скрипт, созданный командой `bash <(curl ...)`;
- для отката сохраняется установленный скрипт из `/opt/MIRA-TV/mira-tv.sh`, резервно используется `/usr/local/bin/mira-tv`;
- обновление, запущенное напрямую из однострочного bootstrap-меню, теперь создаёт временную резервную копию так же, как запуск через установленную команду `mira-tv`;
- добавлена regression-проверка, запрещающая использовать `BASH_SOURCE` как источник установщика внутри функции резервного копирования.

## 1.0.2 — 29 августа 2026

Обновление установщика и восстановления после неудачного обновления.

### Обновление приложения

- в меню оставлен один пункт проверки обновления;
- если установлена последняя версия, установщик сообщает об этом и ничего не меняет;
- если доступна новая версия, установщик показывает её и спрашивает `Обновить? [y/N]`;
- перед началом обновления создаётся временная резервная копия текущих файлов приложения, `.env`, установщика, текущей Git-ревизии и базы PostgreSQL;
- при успешном обновлении временная копия автоматически удаляется;
- если обновление или проверка запуска новой версии завершается ошибкой, установщик автоматически возвращает предыдущую версию приложения, настройки и базу данных;
- загруженные изображения и видео обычным обновлением не удаляются и не копируются без необходимости.

### Управление

- первая установка запускается одной командой `bash <(curl -Ls …/mira-tv.sh)` и сразу открывает меню;
- если скрипт запущен обычным пользователем, административные операции сами запрашивают права через `sudo`;
- пункт `Логи` сохранён отдельным пунктом меню;
- в меню установщика добавлен сброс пароля администратора;
- новый пароль создаётся автоматически по текущим правилам безопасности;
- после сброса старые веб-сессии этого администратора завершаются;
- перед удалением приложения требуется подтверждение `YES`;
- перед удалением приложения вместе со всеми данными требуется отдельное подтверждение `YES` и показывается предупреждение о безвозвратном удалении.

## 1.0.1 — 29 августа 2026

Исправление совместимости серверной установки с современными версиями Docker Engine.

### Исправлено

- компонент HTTPS обновлён до Traefik `3.7.12`;
- устранена ошибка подключения Traefik к Docker Engine 29, при которой в журнале появлялось сообщение `client version 1.24 is too old`;
- Docker-образ Traefik закреплён по точной версии и digest, чтобы обновления внешнего образа не меняли поведение уже выпущенной версии MIRA-TV;
- проверка версии в CI больше не зависит от вручную прописанного номера релиза и сверяет остальные файлы с версией из `package.json`.

## 1.0.0 — 29 августа 2026

Первая версия новой самостоятельной линии MIRA-TV.

### Название и структура проекта

- проект полностью переведён на название MIRA-TV;
- версия приложения начинается с `1.0.0`;
- основной каталог установки — `/opt/MIRA-TV`;
- вся серверная часть работает как один Docker Compose проект `mira-tv`;
- обычные команды `docker compose` работают без дополнительных файлов и специальных параметров.

### Работа телевизоров

- телевизор показывает меню через страницу MIRA-TV Player;
- подключение телевизора выполняется по QR-коду или короткому коду;
- последняя успешно показанная версия экрана сохраняется на телевизоре;
- при временной потере связи экран продолжает показывать сохранённое меню;
- после восстановления связи телевизор автоматически проверяет изменения;
- если изменена только часть экрана, остальные части не создаются заново без необходимости.

### Изображения и видео

- изображения и видео передаются по HTTPS;
- дополнительный файловый сервер больше не требуется;
- уже загруженные файлы могут использоваться повторно из локального кэша телевизора;
- видео воспроизводится средствами браузера без ручной покадровой обработки в JavaScript;
- скрытые видео и анимации приостанавливаются, когда их результат не виден.

### Сервер

- данные хранятся в PostgreSQL;
- панель управления и API работают на Node.js/Express;
- HTTPS обслуживается встроенным в Docker Compose прокси;
- база данных не публикуется напрямую в интернет.

### Производительность

- статическое меню создаётся только после запуска или реального изменения;
- при нормальном соединении телевизор не выполняет частый постоянный опрос сервера;
- резервная проверка используется только когда основное соединение недоступно;
- локальный журнал телевизора ограничен по размеру;
- удалены лишние фоновые операции, которые могли расходовать ресурсы телевизора без видимого результата.

### Документация

- полностью переписана документация проекта;
- добавлены отдельные руководства по установке, настройке, использованию, плееру, анимации, производительности и устранению проблем;
- внутренние документы разработки заменены понятными публичными руководствами.
