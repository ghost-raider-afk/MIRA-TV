# MIRA-TV

Веб-приложение для управления цифровыми меню торговых точек и публикации готовых экранов на телевизоры.

Версия приложения в этой ветке: **`1.7.0`**. Независимая версия установщика: **`1.3.3`**.

## Возможности

- торговые точки и независимые мониторы;
- общий каталог продукции и тары, импорт и экспорт CSV;
- редактор меню с предпросмотром итогового экрана;
- индивидуальные фон, цвета, геометрия и шрифт каждого монитора;
- подготовка JPEG и атомарная публикация через SFTP;
- подключение телевизора по QR-коду или шестизначному коду;
- offline-режим плеера с последним успешно загруженным экраном;
- управление администраторами, оформлением сайта и журналом событий.

## Состав системы

- Node.js 24 — приложение и панель управления;
- PostgreSQL 17 — данные и настройки;
- SFTPGo — доставка файлов на телевизоры;
- Traefik — HTTPS и автоматические сертификаты;
- Docker Compose — изолированный запуск сервисов.

В Интернет публикуются только HTTPS-интерфейс и SFTP-порт. PostgreSQL и служебный HTTP API SFTPGo остаются во внутренней сети. Traefik получает ограниченный read-only доступ к Docker API через socket proxy.

## Требования

- чистая или существующая Ubuntu VPS;
- домен с корректной A/AAAA-записью на VPS;
- открытые порты `80`, `443` и SFTP-порт `2022`;
- запуск установщика через `sudo`.

Docker и необходимые системные пакеты устанавливаются автоматически, если отсутствуют.

## Чистая установка

```bash
curl -fsSL https://raw.githubusercontent.com/ghost-raider-afk/menu-tv-2/installer-v1.3.3/menu-tv-2.sh -o /tmp/menu-tv-2.sh
sudo bash /tmp/menu-tv-2.sh install
```

Установщик запросит домен и email для HTTPS-сертификата, развернёт сервисы и один раз покажет начальные учётные данные. Сохраните их в менеджере паролей.

Проект устанавливается только в `/opt/menu-tv-2.0`. Рабочая конфигурация хранится в `/opt/menu-tv-2.0/.env`.

## Обновление

Сначала обновите системный установщик, затем приложение:

```bash
sudo menu-tv-2.0 update-script
sudo menu-tv-2.0 update
```

Обновление использует только опубликованные GitHub Releases. Перед изменением конфигурации или данных создаётся временная резервная копия; при неуспешной проверке предыдущая версия автоматически восстанавливается.

При переходе на `1.3.2` установщик удаляет устаревшие `APP_CPU_LIMIT`, `DB_CPU_LIMIT` и `SFTP_CPU_LIMIT` из существующего `.env`.

## Управление

```bash
sudo menu-tv-2.0                  # интерактивное меню
sudo menu-tv-2.0 status           # версия, контейнеры и health-check
sudo menu-tv-2.0 update           # обновление приложения
sudo menu-tv-2.0 update-script    # обновление установщика
sudo menu-tv-2.0 reset-admin-password [логин]
sudo menu-tv-2.0 remove           # удалить проект и данные
sudo menu-tv-2.0 remove-script    # удалить только системный скрипт
sudo menu-tv-2.0 purge            # удалить проект, данные и скрипт
```

Команды удаления требуют отдельного подтверждения.

## Ресурсы контейнеров

Для приложения, PostgreSQL и SFTPGo сохранены ограничения памяти и количества процессов:

- `*_MEMORY_LIMIT`;
- `*_PIDS_LIMIT`.

CPU-квоты не используются. В `compose.yaml` нет `cpus:`, а в `.env.example` нет `*_CPU_LIMIT`; Docker самостоятельно распределяет доступный процессор между сервисами.

## Проверки и релизы

Каждое изменение проходит три обязательные группы CI:

- `node-check` — unit-, architecture- и service-тесты;
- `clean-install-smoke` — сборка и запуск полного Docker-стека;
- `browser-visual` — проверка интерфейса в Chromium.

Приложение и установщик версионируются независимо. Стабильные версии приложения публикуются как `vX.Y.Z`, установщика — как `installer-vX.Y.Z`.

Подробности изменений находятся в [CHANGELOG.md](CHANGELOG.md), техническая архитектура — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
