# Как устроена MIRA-TV

Этот документ объясняет устройство MIRA-TV простым языком. Он предназначен для пользователей, администраторов и разработчиков, которым нужно понять общую схему проекта без погружения во внутренние детали каждого модуля.

## Общая схема

MIRA-TV использует три роли:

1. сервер, где хранятся данные, assets и работает панель управления;
2. MIRA Render Agent на компьютере администратора, который при публикации готовит финальный MP4;
3. MIRA-TV Player на телевизоре, который воспроизводит готовую сцену и накладывает live-данные.

```text
Администратор / Scene Editor
    ↓
MIRA Render Agent на ПК
    ↓ готовый H.264 MP4
Сервер MIRA-TV
    ↓ Local-first asset
Телевизор с MIRA-TV Player
    ↓
Video Scene + Live Weather
```

Серверный VPS не обязан кодировать видео и не запускает тяжёлый render worker.

## Что делает сервер

Сервер отвечает за:

- хранение торговых точек, экранов, товаров и настроек;
- вход администраторов в систему;
- сохранение изменений меню;
- хранение изображений и видео;
- подключение телевизоров;
- передачу телевизору только актуальных данных;
- журнал событий и диагностику.

### База данных

MIRA-TV использует PostgreSQL.

В базе хранятся:

- пользователи;
- торговые точки;
- экраны;
- каталог товаров;
- настройки меню;
- настройки анимации;
- информация о подключённых телевизорах;
- служебные записи и журнал событий.

Изображения и видео не хранятся внутри таблиц базы данных. Они находятся в отдельном каталоге приложения и выдаются телевизорам через HTTPS.

### Веб-приложение

Серверная часть написана на Node.js и Express.

Она обслуживает панель администратора, запросы телевизоров и загрузку файлов.

## Что делает телевизор

Телевизор открывает страницу MIRA-TV Player в браузере.

Плеер:

- получает настройки своего экрана;
- в основном режиме скачивает заранее подготовленный MP4 сцены;
- воспроизводит этот MP4 циклично;
- показывает погоду отдельным live-слоем поверх видео;
- сохраняет последнюю успешно показанную версию и необходимые assets локально;
- продолжает показ при кратковременной потере связи;
- использует существующий live renderer как безопасный fallback, если baked video ещё не готово или недоступно.

Тяжёлые декоративные анимации, таблица меню и цены в основном режиме не пересчитываются телевизором каждый кадр.

## Что происходит при изменении меню

Когда администратор сохраняет изменение:

1. сервер записывает новые данные;
2. сервер сообщает нужному телевизору, что экран изменился;
3. телевизор запрашивает актуальные данные;
4. обновляются только изменившиеся части экрана;
5. после успешного показа новая версия сохраняется как рабочая копия на телевизоре.

Если ничего не менялось, меню не строится заново без причины.

## Работа без сети

MIRA-TV хранит на телевизоре последнюю успешно показанную версию экрана.

Если интернет или сервер временно недоступны:

- телевизор продолжает показывать прежнее рабочее меню;
- уже загруженные изображения и видео остаются доступными локально;
- после восстановления связи плеер проверяет, появились ли изменения.

Подробнее: [PLAYER.md](PLAYER.md).

## Как передаются изменения

Меню, изображения и видео телевизор получает по защищённому HTTPS-соединению.

Дополнительно плеер поддерживает лёгкое постоянное соединение с сервером. Оно нужно только для быстрого уведомления о том, что экран изменился.

Само меню и видео через такое уведомление не передаются.

Если постоянное соединение временно недоступно, плеер изредка проверяет сервер обычным HTTPS-запросом.

## Как хранятся данные на телевизоре

Плеер использует стандартное локальное хранилище браузера.

В нём сохраняются:

- последняя рабочая версия экрана;
- нужные файлы плеера;
- изображения и видео, которые уже были загружены;
- небольшой журнал диагностики.

Это позволяет не загружать одни и те же данные повторно и продолжать показ при временной потере связи.

## Отображение меню

Экран состоит из независимых частей. Например:

- фон;
- основное меню;
- изображения или видео;
- название или логотип;
- объявления;
- временные сцены и анимация.

Если меняется только одна часть, остальные по возможности остаются нетронутыми.

Например, изменение текста объявления не должно заставлять заново создавать всё меню или перезапускать уже воспроизводящееся видео.

## Видео и анимация

После публикации статичная и декоративно-анимированная часть экрана подготавливается MIRA Render Agent на компьютере администратора как H.264 MP4. Телевизор в основном режиме воспроизводит готовую сцену как обычное видео.

Погода остаётся живым слоем поверх видео и использует существующую логику обновления.

Старый live renderer сохраняется как fallback и как каноническая основа для Preview/Render Agent, но постоянная генерация декоративных кадров на слабом TV больше не является целевой архитектурой.

Подробнее: [RENDER-AGENT.md](RENDER-AGENT.md), [ANIMATION.md](ANIMATION.md) и [PERFORMANCE.md](PERFORMANCE.md).

## Docker

Вся серверная часть запускается одним Docker Compose проектом.

В него входят:

- веб-приложение MIRA-TV;
- PostgreSQL;
- HTTPS-прокси;
- небольшой служебный контейнер для подготовки каталога загружаемых файлов.

Все компоненты описаны в одном `compose.yaml`.

Поэтому после установки достаточно обычных команд:

```bash
cd /opt/MIRA-TV
sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs -f
sudo docker compose down
```

Отдельно создавать Docker-сети вручную не требуется.

## Сеть и безопасность

Снаружи сервера должны быть доступны только веб-порты `80` и `443`.

База данных не публикуется напрямую в интернет.

Телевизор и панель управления работают через HTTPS.

Служебные пароли и секреты находятся в `/opt/MIRA-TV/.env` и не должны публиковаться в репозитории.

## Передача файлов

Дополнительный файловый сервер не требуется. Телевизор получает данные, изображения и видео непосредственно от MIRA-TV по HTTPS.

## Основной принцип проекта

Подготовительная работа должна выполняться на наиболее подходящем устройстве. Для видеорендера это компьютер администратора, а не слабый TV и не маломощный VPS.

Для телевизора главный принцип простой:

> Если экран не изменился и ничего не должно двигаться, плеер должен почти ничего не делать.
