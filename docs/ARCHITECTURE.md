# Архитектура MIRA-TV

Схема ниже соответствует опубликованному серверу и текущему TV Player.

## Компоненты

~~~text
Администратор / менеджер (браузер)
              │ HTTPS
              ▼
   Traefik 3 / Caddy 2
              │
              ▼
  Node.js 24+ / Express 5
   ├─ API и права доступа ── PostgreSQL 17
   ├─ каталог / экраны / CRM
   ├─ weather и серверный кэш
   ├─ /site-assets/
   └─ WebSocket и fallback API
              │
              ▼
        MIRA-TV Player
   Local-first + статический SVG
~~~

Базовый `compose.yaml` содержит `app`, `db` и init-контейнер для assets. Reverse proxy вынесен в `compose.traefik.yaml` (Traefik, default) или `compose.caddy.yaml` (Caddy). `COMPOSE_FILE` в `.env` выбирает один из них. Наружу опубликованы TCP 80/443 (Caddy также UDP 443), а `app:8080` и `db:5432` остаются внутренними. Внешняя Docker-сеть `mira-tv-proxy` создаётся установщиком; приватная `mira-tv-internal` используется для БД. Readiness приложения — `/readyz`; база, assets и сертификаты хранятся в постоянных Docker volumes.

Отдельный `compose.bot.yaml` пока только описывает **будущий** Telegram/MAX-бот с проектным внутренним портом `8090`; рабочего runtime нет. См. [REVERSE-PROXY.md](REVERSE-PROXY.md) и [BOT.md](BOT.md).

## Общий рендеринг сцены

Порядок сцены: **menu → theme → scene**.

- `PlayerSceneRenderer` — канонический renderer для TV и Preview.
- Таблица строится общим render model/layout, а `FlatMenuRenderer` выводит векторный SVG.
- `SceneElementRenderer` выводит статические элементы: текст, логотипы/изображения и generic weather.
- Премиальная, меловая и брендовая темы — пресеты общего renderer. Существует отдельный «Конструктор темы» и сохранение пользовательских тем.
- Фон, clipping, координаты, размеры, масштаб, поворот, порядок слоёв и прозрачность не должны изменять геометрию других элементов.
- Preview и TV используют одно каноническое полотно с пропорциональным масштабированием; отдельный renderer или визуальные обходы в Preview недопустимы.

Текущий production-режим — **статический live-render**. Video-element и runtime видеосцен не входят в него; штатному меню не нужен цикл кадров.

## Погода

Поставщиков погоды опрашивает backend, не телевизор. Предусмотрены fallback между провайдерами, серверное кэширование последнего рабочего ответа и timezone выбранного города.

У системного пресета за погоду отвечает его utility slot. Конструктор темы поддерживает generic weather как отдельный scene element. Одну погоду нельзя одновременно выводить двумя владельцами.

## Данные и доступ

PostgreSQL хранит пользователей и права, торговые точки, каталог, экраны и меню, сцены, темы, регистрации ТВ, заявки CRM, уведомления и историю действий. Файлы пользовательских изображений обслуживаются через собственный сервер из постоянного volume. Исторические миграции БД сохраняются ради совместимости, даже если соответствующий функционал больше не поддерживается.

Роль менеджера ограничивается разрешёнными торговыми точками. Внесение изменений через CRM проверяется сервером, с учётом прав, ревизий и статуса заявки.

## TV: обновления и надёжность

Состояние разделено на `screen`, `menu`, `scene`, `content_manifest`, `runtime`. WebSocket сообщает об изменениях, при отсутствии связи используется редкая резервная синхронизация по HTTPS.

Плеер получает только изменившиеся компоненты, заранее подготавливает нужные assets и не уничтожает ACTIVE/LKG до успешного переключения. PREVIOUS нужен для восстановления. Service Worker и браузерное хранилище обеспечивают локальный shell и необходимые `/site-assets/`.

После восстановления сети TV сверяет версии и продолжает работу без обязательной ручной перезагрузки. Ограничения браузерного хранилища и принудительная очистка данных самим устройством остаются внешними рисками.

## Требования к изменениям

Приоритет: **надёжность → архитектура → производительность → UX → скорость**. Не создавать дубли renderer, не добавлять фоновые циклы и зависимости без необходимости. Сохранять PostgreSQL, старые сцены, регистрацию устройств, API, Docker volumes и поведение установщика.

Проверки: Scene Editor → Preview → TV, desktop/mobile, слабый Android TV, LKG/offline, unit/contract, DB, Docker, Playwright и performance. Окончательный релиз требует полного Final CI на финальном HEAD, проверки равенства Git tree после merge и production smoke.
