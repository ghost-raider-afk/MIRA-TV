# Полный backup и перенос MIRA-TV

MIRA-TV поддерживает полный перенос на другой физический сервер без повторной привязки телевизоров, если сохраняется доменное имя.

## Что сохраняет полный backup

Файл `.mirabackup` содержит:

- логический dump PostgreSQL;
- файл `.env` со всеми постоянными секретами;
- пользовательские изображения, видео, логотипы и другие site assets;
- состояние Let's Encrypt/TLS;
- версию MIRA-TV;
- точный Git revision релиза;
- домен;
- контрольные суммы SHA-256.

Исходный код и Docker images в backup не копируются. При восстановлении установщик получает из GitHub точный релиз, указанный в backup, и проверяет его Git revision.

## Почему телевизоры не нужно привязывать заново

Привязки телевизоров, их идентификаторы и связи с экранами находятся в PostgreSQL. Полное восстановление возвращает эту базу без изменения идентификаторов.

Также восстанавливается `SESSION_SECRET` и остальные постоянные секреты из `.env`. Новые секреты при восстановлении не генерируются.

После переключения DNS на новый сервер телевизор продолжает обращаться к тому же домену и получает свою прежнюю конфигурацию.

## Создание полной резервной копии

Через меню:

```bash
mira-tv
```

Выберите **«Создать полную резервную копию»**.

Или напрямую:

```bash
sudo mira-tv backup
```

По умолчанию файл создаётся в:

```text
/var/backups/mira-tv/
```

Можно указать другой файл или каталог:

```bash
sudo mira-tv backup /root/server-move.mirabackup
```

Файл создаётся с правами `0600`. Он содержит конфиденциальные данные, поэтому передавать его нужно только по защищённому каналу.

## Проверка backup

Перед переносом обязательно выполните:

```bash
mira-tv verify-backup /path/to/file.mirabackup
```

Проверяется точный состав архива, версия формата, версия MIRA-TV, домен и контрольные суммы всех компонентов. Неожиданные элементы архива отклоняются до извлечения.

## Восстановление на новом сервере

Восстановление предназначено для чистого Ubuntu-сервера без существующей установки MIRA-TV и без старых Docker volumes проекта.

Запустите актуальный установщик MIRA-TV и выберите **«Восстановить сервер из резервной копии»**, либо выполните:

```bash
sudo bash mira-tv.sh restore-backup /path/to/file.mirabackup
```

Установщик:

1. проверяет backup до изменения сервера;
2. устанавливает Docker при необходимости;
3. получает точный релиз MIRA-TV из GitHub;
4. сверяет Git revision с manifest backup;
5. восстанавливает исходный `.env`;
6. восстанавливает PostgreSQL;
7. восстанавливает пользовательские файлы;
8. восстанавливает TLS-состояние;
9. запускает весь стек;
10. проверяет `/readyz`.

Только после успешного восстановления следует переключать DNS домена на IP нового сервера.

## Рекомендуемый порядок переезда

1. Создать backup на старом сервере.
2. Проверить backup командой `verify-backup`.
3. Передать файл на новый сервер по защищённому каналу.
4. Восстановить MIRA-TV на новом сервере.
5. Проверить работу нового сервера до изменения DNS.
6. Сделать финальный backup непосредственно перед переключением.
7. Восстановить финальный backup на новом сервере.
8. Переключить A/AAAA-записи домена.
9. Старый сервер не удалять до подтверждения стабильной работы нового.

## Совместимость

Полный backup восстанавливает именно ту версию MIRA-TV, на которой он был создан. Обновление MIRA-TV выполняется отдельным шагом после успешного восстановления.

Это исключает одновременное изменение сервера и схемы приложения.

## Следующий этап бесшовной миграции

Архитектурой предусмотрен отдельный migration mode:

- кратковременная блокировка изменений конфигурации на старом сервере;
- финальный согласованный snapshot;
- relay старого сервера на новый на время распространения DNS;
- автоматическая проверка количества и идентичности привязанных телевизоров до переключения.

Этот этап реализуется отдельно от формата backup/restore, чтобы не давать web-приложению доступ к Docker socket или host filesystem и не смешивать две независимые зоны риска.
