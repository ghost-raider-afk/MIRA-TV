# Telegram / MAX-бот MIRA-TV: архитектура и установка

**Статус: только проектирование.** На опубликованном сервере ещё нет рабочего приложения бота, его Dockerfile, авторизации Mini App и обработчиков Telegram/MAX. `compose.bot.yaml` — будущий отдельный Docker-файл, он намеренно не включён в производственный `COMPOSE_FILE`. Команда `mira-tv bot` объясняет это и не запускает несуществующий образ.

## Назначение

- Администратор: уведомления о новых/изменённых заявках, состояние ТВ и торговых точек, краткий дашборд, история подключений и отключений.
- Менеджер: создание и отслеживание CRM-заявок, комментарии и доработка в пределах назначенных точек.
- Все заявки будут обрабатываться **существующим серверным CRM**, без второй копии бизнес-логики и БД.

## Согласованные правила событий

Подтверждение потери связи TV: **120 секунд**. Восстановление связи: **уведомление включено**. Повторное сообщение по тому же инциденту: **отключено**. Краткое пропадание WebSocket до истечения 120 секунд не должно запускать тревогу, а перезапуск сервера не должен создавать ложные массовые отключения. История событий и очередь доставки сохраняются в PostgreSQL.

## Будущие сервисы и порты

| Сервис | Внутренний порт | Сеть | Публичный порт |
| --- | --- | --- | --- |
| `app` | `8080/tcp` | `mira-tv-proxy` + `mira-tv-internal` | Нет; доступ через HTTPS proxy |
| `db` | `5432/tcp` | только `mira-tv-internal` | Нет |
| `bot` (план) | `8090/tcp` | `mira-tv-proxy` | Нет; только через proxy |
| `proxy` Traefik/Caddy | `80/tcp`, `443/tcp`, для Caddy ещё `443/udp` | `mira-tv-proxy` | 80/443 |

Бот не получает прямой доступ к PostgreSQL: сервер MIRA-TV определяет состояние ТВ и права доступа, затем отдаёт уполномоченные данные через внутренний API `http://app:8080`. Telegram/MAX будут двумя адаптерами одной системы событий. Секреты ботов должны храниться вне GitHub.

## Docker-файл и дальнейшая установка

Файл [`compose.bot.yaml`](../compose.bot.yaml) показывает будущий контейнер с `profiles: [bot]`, `BOT_PORT=8090`, внутренним API и отсутствием опубликованных портов. Образ `mira-tv-bot:local` пока не существует. После реализации потребуется рабочий Dockerfile бота, проверка авторизации, healthcheck, подключение к выбранному proxy и отдельная проверка CI.

После готовности бота будет документирован порядок добавления третьего Compose-файла к `COMPOSE_FILE` и управления его жизненным циклом. **Сейчас не используйте** `docker compose --profile bot up`: это не установка бота.

## Проверки, обязательные перед запуском

1. Привязка аккаунта мессенджера к пользователю MIRA-TV через одноразовую процедуру, запрет доступа к чужим точкам.
2. Корректное создание и обработка заявки через CRM API, с проверкой роли на сервере и журналом действий.
3. Фильтрация offline в течение 120 секунд, единичная тревога и уведомление после восстановления.
4. Сохранение очереди сообщений при рестарте бота и отсутствие повторной доставки уже подтверждённых уведомлений.
5. Отсутствие изменений в `app`, Player, постоянных данных, Docker volumes и регистрации телевизоров при обновлении контейнера бота.

Пошаговая установка всей платформы, Docker-сети, Traefik или Caddy и проверка портов — [REVERSE-PROXY.md](REVERSE-PROXY.md).
