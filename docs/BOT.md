# Telegram/MAX-бот MIRA-TV

## Статус

Отдельный Docker-контейнер и защищённые Telegram/MAX webhook, серверная авторизация, мониторинг ТВ и чтение CRM-уведомлений реализованы в проектной ветке. До публикации релиза установка через стандартный обновлятор недоступна. Полноценное создание CRM-заявок из переписки остаётся следующим этапом; текущие команды не создают и не меняют заявки.

## Изоляция

- Основной production Compose (app, PostgreSQL, Traefik) продолжает работать без конфигурации бота. Дополнительный compose.bot.yaml применяется только при установке бота.
- Внешние порты остаются 80/443 на существующем Traefik; бот слушает внутренний 8090, без публикации на хост.
- Сеть mira-tv-bot соединяет только bot, app и proxy. PostgreSQL расположен в mira-tv-internal, и боту не выдаются его логин или пароль.
- Доступ к внутреннему API MIRA-TV требует отдельный 64-символьный BOT_INTERNAL_API_TOKEN. Провайдерские webhook проверяются секретами Telegram/MAX. Все ID сверяются с действующим пользователем CRM.
- Идентификаторы Telegram и MAX назначаются администратором в Настройки → Пользователи → Telegram и MAX. Telegram Admin ID в установщике сам по себе НЕ предоставляет права. Самостоятельная привязка отложена.

## Установка после выпуска релиза

1. Создайте Telegram-бота через BotFather, сохраните токен и числовой Telegram User ID. При необходимости создайте бота в MAX и получите токен и ID.
2. Подготовьте отдельный DNS-адрес, например bot.example.com, с A/AAAA на действующий Traefik MIRA-TV. На домене должен работать доверенный HTTPS-сертификат, внешний порт 443.
3. Запустите `sudo mira-tv bot` или пункт 9 главного установщика. Домен, Telegram-токен и ID обязательны; MAX можно пропустить. Секреты сохраняются только в `.env.bot` (0600), защищённая копия — `/var/lib/mira-tv/bot.env`.
4. Проверьте состояние через `sudo mira-tv status` и `sudo mira-tv logs`, а также HTTPS-запрос к `https://bot.example.com/healthz`.
5. После проверки DNS и HTTPS выполните `sudo mira-tv bot-register` (пункт 10). Регистрация Telegram setWebhook и MAX POST /subscriptions проводится только по этой явной команде; секреты не печатаются.
6. В админке MIRA-TV назначьте пользователям Telegram ID/MAX ID. Напишите боту `/start`. Неавторизованные пользователи не получают данные точек и заявок.

Для MAX обязательно проверить доверие к TLS-цепочке platform-api2.max.ru в контейнере. Нельзя отключать проверку сертификата или устанавливать недоверенные CA ради успешного подключения.

## Работа

- `/start` и `/help`: список команд.
- `/status`: состояние доступных пользователю ТВ. Менеджер видит только закреплённые точки; администратор — всю сеть.
- `/requests`: последние адресные CRM-уведомления пользователя. Никакие заявки других пользователей не возвращаются.
- ТВ считается отключённым после 120 секунд отсутствия WebSocket. Краткий обрыв не создаёт сообщение; восстановление после подтверждённого обрыва создаёт отдельное уведомление.
- CRM-события берутся из существующего request_notifications. Durable outbox и серверное состояние TV-инцидентов хранятся в PostgreSQL; очередь выдаёт задачи с арендой и повторной доставкой. Перезапуск бота не уничтожает очередь.
- Дубликаты одного TV/CRM-события не создаются благодаря event_key. Из-за отсутствия сквозного idempotency API у мессенджеров повторная доставка при потере подтверждения провайдера всё же возможна (семантика at least once).

## Безопасное обслуживание

Перед обновлением MIRA-TV стандартный установщик делает резервные копии БД и assets. `.env.bot` включён в локальную защищённую копию установщика и дополнительно сохраняется отдельно; обычное удаление MIRA-TV не удаляет `/var/lib/mira-tv/bot.env`, а purge удаляет.
Нельзя коммитить `.env.bot`, выводить токены в журналы или предоставлять Docker bot доступ к PostgreSQL. Сам TV Player не делает запросов к мессенджерам, не зависит от Telegram/MAX и продолжает работать при отключении бота.

## Проверки перед релизом

Обязательны Node/DB, Compose production и overlay, browser/visual, безопасность, `/readyz`, базовый сценарий Telegram/MAX, права manager/admin, 120-секундное подтверждение, уведомление о восстановлении и отказ API мессенджера. Тесты на реальном Android TV отдельно проверяют, что изменение не влияет на TV Runtime.
