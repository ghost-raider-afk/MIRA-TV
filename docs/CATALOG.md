# Каталог и цены

## Цель

Каталог MIRA-TV должен быть универсальным и подходить не только для пива или ресторанов.

Текущие понятия «Продукция» и «Тара» объединяются в один пользовательский раздел **Каталог**. Тара становится обычной категорией или типом позиции.

## Универсальная позиция

Базовые данные:

```text
Название
Категория
Описание
Базовая цена
Базовое количество/объём
Единица измерения
Изображение
Активность
Дополнительные свойства
```

Дополнительные свойства зависят от категории и не должны превращать основную таблицу БД в набор полей только для одного бизнеса.

## Пример: пиво

Для категории «Пиво» могут появляться свойства:

- крепость;
- цвет: светлое, тёмное и другие варианты;
- фильтрация: фильтрованное, нефильтрованное;
- другие специфические характеристики по мере необходимости.

Эти поля не должны отображаться для еды, услуг или тары.

## Другие категории

Один и тот же каталог может содержать:

- напитки;
- еду;
- упаковку и тару;
- дополнительные товары;
- услуги;
- любые другие позиции, которые пользователь хочет вывести в Scene Table.

## Базовая цена и объём

Для товара, цена которого зависит от объёма, хранится базовая пара:

```text
base_quantity
base_unit
base_price
```

Например:

```text
1 л = 400 ₽
```

## Автоматический расчёт другого объёма

В Table Element пользователь может добавить ценовую колонку для любого нужного объёма.

Формула:

```text
target_price = base_price × target_quantity / base_quantity
```

Пример:

```text
0.5 л = 200 ₽
1.0 л = 400 ₽
1.5 л = 600 ₽
```

Расчёт должен учитывать совместимые единицы, например `500 мл = 0.5 л`.

## Ручная цена

Линейная формула не всегда отражает реальную коммерческую цену. Поэтому пользователь может задать Price Variant вручную.

```text
1.5 л
автоматически: 600 ₽
ручная цена: 550 ₽
```

При наличии ручного варианта используется он.

## Денежная точность

Деньги нельзя считать обычным плавающим `Number` как источником истины. На сервере используются точные денежные значения — `NUMERIC/DECIMAL` или минимальные денежные единицы.

TV Player получает уже рассчитанное нормализованное значение и не содержит бизнес-логику цены.

## Table Element

Таблица сцены должна позволять выбирать:

- категорию или набор позиций;
- фильтр активных товаров;
- сортировку;
- набор колонок;
- отображаемые свойства;
- один или несколько объёмов цены;
- формат и округление отображения;
- визуальный стиль таблицы.

Таблица не является отдельным «редактором меню». Это элемент Scene с data binding на каталог.

## Миграция текущих данных

Существующие товары и тара не должны быть потеряны. Перед серверным переходом новой модели требуется отдельная миграция с проверкой количества позиций, цен, связей и результата рендера.
