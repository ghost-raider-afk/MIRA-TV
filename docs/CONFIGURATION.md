# Конфигурация MIRA-TV

## Единый источник настроек

Серверные лимиты и эксплуатационные параметры должны иметь один источник истины — `.env`.

```text
/opt/MIRA-TV/.env
```

Код не должен иметь скрытый второй набор лимитов, расходящийся с `.env`.

## Стабильная линия

Текущие параметры стабильной версии включают домен/HTTPS, PostgreSQL, правила паролей и сессий, лимиты входа, параметры Player, журналы, размеры запросов и медиа, а также Docker memory/pids limits.

Актуальный полный список всегда находится в `.env.example` соответствующего релиза.

Файл `.env` содержит секреты и не должен публиковаться.

## Важное различие для prototype

Новая Scene Architecture ещё не имеет финального набора серверных env-параметров. Нельзя заранее придумывать и документировать переменные, которые код пока не использует.

Новый параметр добавляется в `.env.example`, конфигурационный слой, тесты и документацию одновременно с функцией, которой он реально управляет.

## Размеры сцены

Существующие `SCREEN_MAX_WIDTH` и `SCREEN_MAX_HEIGHT` относятся к текущей экранной модели стабильной линии.

Они не должны автоматически стать ограничением новой панорамной Scene Architecture: глобальный Canvas из нескольких Full HD TV может быть шире 1920 px.

Перед серверной реализацией нового конструктора потребуется отдельная модель лимитов, учитывающая:

- размер одного физического TV;
- максимальное количество TV в горизонтальной группе;
- максимальный логический Canvas;
- ресурсные ограничения Player и медиа.

Конкретные env-переменные фиксируются только после реализации.

## Медиа

Лимиты загрузки должны задаваться сервером и одинаково применяться в API и UI. Пользовательский интерфейс не должен иметь собственные захардкоженные значения.

Media Pipeline должен проверять реальное содержимое файла, а runtime Docker image обязан содержать все внешние инструменты, на которые опирается серверная валидация.

## Player

Параметры fallback polling, Device Session и локального журнала остаются серверными настройками. Их нельзя дублировать константами в UI.

Новая архитектура позже добавит параметры синхронизации панорамных TV только тогда, когда соответствующий runtime будет реализован и протестирован.

## Обновление `.env`

Upgrade path должен сохранять существующие секреты и добавлять только отсутствующие новые параметры. Нельзя генерировать новый пароль PostgreSQL для уже существующего persistent database volume и ожидать, что старая база автоматически примет его.
