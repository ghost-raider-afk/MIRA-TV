# Контрольный список установки и обновления

Применяется после установки, обновления и **ручного** восстановления. Автоматический перенос сервера по SSH ещё не входит в текущий стабильный установщик.

## 1. Система и Docker

~~~bash
cd /opt/MIRA-TV
sudo docker compose config --quiet
sudo docker compose ps
sudo docker compose logs --tail=200
~~~

Проверьте, что `db`, `app`, `proxy` работают, init-контейнеры завершились без ошибки, а `app` healthy. Убедитесь, что Docker Compose поддерживает `gw_priority`.

## 2. Готовность приложения

~~~bash
sudo docker compose exec -T app node -e "fetch('http://127.0.0.1:8080/readyz').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"
~~~

Проверьте HTTPS по своему домену, наличие сертификата и успешный вход администратора. Наружу должны быть доступны только необходимые порты; PostgreSQL не должен иметь публичного listener.

## 3. Постоянные данные

Проверьте сохранность существующих торговых точек, пользователей, каталога, сцен, тем, прав менеджеров, CRM и записей регистрации телевизоров. Не создавайте/удаляйте тестовые записи на рабочем сервере без необходимости.

Docker volumes для БД, site assets и сертификатов нельзя удалять в ходе обычного обновления. `docker compose down -v` **не применять**.

## 4. Editor → Preview → TV

Откройте существующий экран. Проверьте геометрию таблицы, фона, логотипов, текста и погоды в Editor, Preview и реальном TV. Проверьте системные темы и конструктор, отсутствие двойной погоды и правильное масштабирование полотна.

Измените безопасное значение, сохраните и проверьте автоматическое получение дельты конкретным TV без принудительной перезагрузки.

## 5. Local-first и восстановление связи

После полной загрузки сцены временно отключите TV от сервера и проверьте сохранение ACTIVE/LKG, в том числе после безопасного перезапуска браузера. Восстановите связь и проверьте получение нового состояния через WebSocket или fallback.

Проверьте, что ошибка загрузки обязательного asset не заменяет рабочую сцену пустым экраном. Не очищайте браузерный кэш во время этого испытания.

## 6. Пользователи и CRM

Проверьте разграничение точек у менеджера, создание/просмотр заявки, отображение имён точек и товаров, русские статусы и сообщения журнала. В уведомлениях должны появляться только события заявок. Проверяйте без внесения нежелательных производственных изменений.

## 7. Слабый Android TV

Проверяйте старый Chromium/WebView: поддержка CSS-геометрии, SVG-таблица, полный фон и отсутствие clipping. При статическом показе не должно быть постоянного render-loop, а интерфейс админки не должен иметь переполнений на desktop/mobile.

## 8. Проверки обновления и безопасность

~~~bash
sudo mira-tv status
sudo mira-tv update
~~~

`mira-tv update` сначала предлагает обновление и требует подтверждения — не подтверждайте его ради проверки на production. Не существует отдельной команды `check-update`.

Проверьте, что версия приложения согласована с опубликованным релизом, `.env` и Docker volumes сохранены, пароли/токены не попали в логи или GitHub. При проблеме используйте [TROUBLESHOOTING.md](TROUBLESHOOTING.md).
