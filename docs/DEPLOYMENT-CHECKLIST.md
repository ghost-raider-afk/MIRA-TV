# Deployment и acceptance checklist MIRA-TV

## Статус веток

`main` — рабочая стабильная линия. `prototype` — разработка нового Scene Editor и не предназначена для production deployment.

## Базовая проверка стабильной установки

```bash
cd /opt/MIRA-TV
sudo docker compose config --quiet
sudo docker compose ps
sudo docker compose logs --tail=200
```

Проверить HTTPS, вход администратора, PostgreSQL, сохранение данных после restart, подключение TV, получение обновлений и Last Known Good при временной потере сети.

## Readiness

Рабочее обновление считается успешным только после реальной проверки готовности приложения и обязательных зависимостей. Сам факт запущенного процесса/контейнера недостаточен.

## Persistent state

Перед обновлением или миграцией проверить, что backup/rollback охватывает:

- PostgreSQL;
- `.env` и необходимые секреты;
- Media/Asset Storage;
- версию приложения и установщик, если они участвуют в recovery.

Rollback должен возвращать согласованное состояние всех частей.

## Acceptance новой Scene Architecture

До замены стабильной экранной модели новая архитектура должна пройти отдельные сквозные проверки.

### Scene Editor

- создать Scene;
- добавить/удалить/переставить Slides;
- добавить каждый тип Element;
- drag/resize без заметных рывков;
- Undo/Redo;
- закрыть и снова открыть Draft без потери геометрии;
- Preview совпадает с Scene Renderer Player.

### Catalog

- реальные позиции попадают в Table Element;
- свойства категорий не смешиваются;
- цена другого объёма рассчитывается точно;
- ручной Price Variant имеет приоритет;
- миграция не теряет старые товары и тару.

### Media

- изображение и видео проходят серверную валидацию;
- production Docker image содержит необходимые runtime-зависимости;
- Asset не удаляется, пока используется Scene/Revision;
- неиспользуемые Asset очищаются безопасно.

### Один TV

- Template назначается торговой точке;
- физический Device получает правильную сцену;
- изменения приходят без ручной перезагрузки;
- offline сохраняет Last Known Good.

### Горизонтальная группа TV

- 2, 3 и более Player получают правильные viewport;
- границы Canvas совпадают с Editor;
- все TV используют одну версию Scene и timeline;
- отсутствие одного TV не ломает остальные;
- после восстановления Device возвращается в синхронное состояние.

### Производительность

Проверять не только мощный ПК, но и самый слабый целевой телевизор. Статическая сцена не должна создавать постоянную CPU/GPU/сетевую нагрузку без причины.

## Запрет преждевременной миграции

Пока UX, Scene Schema, Catalog binding и Player parity не доказаны тестами, новую модель нельзя объявлять стабильной и нельзя удалять старый рабочий путь из `main`.
