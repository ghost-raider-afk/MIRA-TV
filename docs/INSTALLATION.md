# Установка MIRA-TV

## Какая ветка предназначена для рабочего сервера

Для эксплуатации используется стабильная ветка `main` и опубликованные релизы.

Ветка `prototype` предназначена для разработки новой архитектуры конструктора сцен. Она не является production-релизом и не должна заменять рабочую установку MIRA-TV.

## Быстрая установка стабильной версии

```bash
bash <(curl -Ls https://raw.githubusercontent.com/ghost-raider-afk/MIRA-TV/main/mira-tv.sh)
```

Установщик создаёт `/opt/MIRA-TV`, `.env`, Docker Compose проект и команду `mira-tv`.

## Требования

- Ubuntu;
- доменное имя, направленное на сервер;
- порты `80` и `443`;
- root или sudo;
- доступ в интернет для Docker и GitHub.

## Основные команды

```bash
mira-tv
mira-tv status
mira-tv update
mira-tv reset-admin-password
```

Docker Compose можно использовать напрямую:

```bash
cd /opt/MIRA-TV
sudo docker compose ps
sudo docker compose logs -f
sudo docker compose restart
sudo docker compose down
```

## Обновление

Рабочая установка должна обновляться только на опубликованный стабильный релиз. Экспериментальную ветку `prototype` нельзя подставлять в обычный production update path.

Перед обновлением должны сохраняться все данные, необходимые для полного возврата рабочей системы: приложение, `.env`, PostgreSQL и любые persistent assets, которые новая версия способна изменить.

Успех обновления определяется готовностью приложения, а не только состоянием `container running`. Целевой критерий — успешный readiness check приложения и его обязательных зависимостей.

## Удаление и сохранение данных

Операция «удалить приложение, сохранив данные» обязана сохранять не только Docker volume, но и конфигурацию/секреты, без которых эти данные нельзя снова открыть.

Полное удаление данных должно оставаться отдельной явно подтверждаемой операцией.

## Разработка prototype

`prototype` следует рассматривать как отдельную рабочую ветку разработчика. Её Scene Editor в текущем состоянии использует временное `localStorage` и ещё не имеет финальной серверной модели.

Не переносите prototype-сцены на рабочий сервер как production-данные и не проектируйте миграции PostgreSQL до утверждения Scene Schema.

## После установки стабильной версии

Для текущей рабочей линии используйте существующие экранные возможности. Целевой пользовательский поток новой архитектуры описан в [USAGE.md](USAGE.md) и будет становиться эксплуатационным только после завершения соответствующих этапов roadmap.
