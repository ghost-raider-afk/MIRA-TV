# Установка, обновление и удаление MIRA-TV

Инструкция для опубликованной версии MIRA-TV на **Ubuntu**. Установщик загружает последний стабильный GitHub Release, а не произвольное состояние `main`.

## Подготовка

Необходимы: Ubuntu, доступ `root` или `sudo`, домен с DNS A/AAAA на этот сервер, открытые TCP-порты `80`/`443` и интернет для получения пакетов и Docker-образов. Для Compose требуется версия **2.33.1 или новее** (параметр `gw_priority`). Если Docker или необходимая версия Compose отсутствуют, установщик устанавливает/обновляет их.

## Первичная установка

~~~bash
bash <(curl -Ls https://raw.githubusercontent.com/ghost-raider-afk/MIRA-TV/main/mira-tv.sh)
~~~

В меню выберите **1) Установить**. Скрипт запросит домен (без `https://`), email для сертификата и логин администратора. Пароль администратора, пароль PostgreSQL и сессионный секрет генерируются автоматически. Пароль администратора показывается после установки: сохраните его.

После установки доступны:

- `/opt/MIRA-TV` — рабочий каталог с `compose.yaml`.
- `/opt/MIRA-TV/.env` — приватные параметры и секреты.
- `/var/lib/mira-tv/install.env` — защищённая копия конфигурации, которую использует установщик.
- `/usr/local/bin/mira-tv` — команда управления.

## Меню и команды

~~~text
1) Установить
2) Проверить обновление
3) Статус
4) Перезапустить
5) Логи
6) Сбросить пароль администратора
7) Удалить приложение
8) Удалить приложение и данные
0) Выход
~~~

Открыть меню:

~~~bash
mira-tv
~~~

Поддерживаемые аргументы установленного скрипта:

~~~text
install | update | status | restart | logs | reset-admin-password | remove | purge | menu
~~~

**Отдельной команды `check-update` в стабильном установщике нет.** Для проверки обновлений используйте `mira-tv update` или второй пункт меню: сначала выводятся версии и запрос подтверждения. Команды миграции на новый сервер ещё не включены в релиз.

## Обновление и восстановление

~~~bash
sudo mira-tv update
~~~

Если новая версия отсутствует, ничего не меняется. Если она есть, ответ `y` подтверждает обновление; любой другой ответ отменяет его.

Перед переключением установщик сохраняет временную копию исходных файлов, `.env`, скрипта, Git revision, PostgreSQL dump и site assets. Затем переключает исходники на релизный тег, дополняет `.env` отсутствующими параметрами, проверяет Compose, запускает контейнеры и проверяет `/readyz`.

Если обновление не проходит, запускается автоматическое восстановление предыдущих исходников, базы и site assets. В случае неуспешного отката временная копия сохраняется для ручного восстановления; диагностика записывается в `/var/lib/mira-tv/last-update-failure.log`. Перед обновлением критически важной установки всё равно рекомендуется иметь собственную внешнюю резервную копию.

**Не прерывайте установщик и не удаляйте volume во время обновления/отката.** Обновление приложения само по себе не требует повторной привязки TV.

## Проверка после установки

~~~bash
cd /opt/MIRA-TV
sudo docker compose config --quiet
sudo docker compose ps
sudo docker compose logs --tail=200
sudo docker compose exec -T app node -e "fetch('http://127.0.0.1:8080/readyz').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"
~~~

После этого проверьте HTTPS на домене, вход администратора, создание экрана и подключение TV. [Контрольный список](DEPLOYMENT-CHECKLIST.md).

## Docker Compose

~~~bash
cd /opt/MIRA-TV
sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs -f
sudo docker compose restart
sudo docker compose stop
sudo docker compose start
sudo docker compose down
~~~

`docker compose down` оставляет volumes на месте. **`docker compose down -v` удаляет постоянные данные** — не используйте эту команду при штатном восстановлении.

## Сброс пароля и удаление

~~~bash
sudo mira-tv reset-admin-password
sudo mira-tv remove
sudo mira-tv purge
~~~

`remove` удаляет приложение, сохраняя Docker volumes и конфигурацию для возможного восстановления. `purge` удаляет также данные, секреты и сертификаты; обе операции требуют ввода `YES`.
