# Производительность MIRA-TV

MIRA-TV рассчитана на длительную работу на телевизорах, поэтому одна из главных целей проекта — не тратить ресурсы устройства без необходимости.

## Главное правило

Если содержимое экрана не изменилось и на нём нет активного видео или анимации, плеер должен почти ничего не делать.

Это относится к:

- процессору;
- графике;
- оперативной памяти;
- сети;
- локальному хранилищу;
- энергопотреблению.

## Статическое меню

Обычное меню создаётся при запуске или после изменения его данных.

Если данные остались прежними, повторное создание меню не требуется.

Изменение отдельного элемента экрана также не должно без причины перестраивать остальные части.

## Сеть

При нормальной работе телевизор получает короткое уведомление только после изменения экрана.

Если постоянное соединение временно недоступно, включается резервная проверка сервера. По умолчанию она выполняется редко, чтобы не создавать постоянный сетевой трафик.

## Изображения и видео

Уже загруженные файлы сохраняются локально и используются повторно.

Новый файл загружается только если он действительно нужен текущему экрану и ещё отсутствует на телевизоре.

После успешного перехода на новую версию экрана старые ненужные файлы могут быть удалены.

## Видео

Видео воспроизводится обычным механизмом браузера.

MIRA-TV не копирует целый видеофайл в память JavaScript для обработки каждого фрагмента и не декодирует кадры вручную.

Это позволяет браузеру использовать встроенные возможности телевизора, включая аппаратное ускорение там, где оно доступно.

## Невидимые элементы

Если видео или анимация скрыты и их результат не виден пользователю, они должны быть приостановлены.

Это особенно важно:

- во время полноэкранной временной сцены;
- когда плеер показывает экран подключения;
- когда вкладка браузера скрыта.

## Локальное хранение

На телевизоре хранится только необходимая информация:

- последняя рабочая версия экрана;
- используемые файлы;
- небольшой журнал диагностики.

Журнал ограничен по количеству записей и размеру. Он не должен расти бесконечно.

Если журнал пуст, плеер не должен постоянно открывать локальную базу данных только для повторной проверки пустой очереди.

## Сервер и телевизор

Если выбор стоит между дополнительной подготовительной работой на сервере и постоянной нагрузкой на телевизор, предпочтение отдаётся серверу.

Телевизор должен в основном заниматься тем, для чего он нужен: показывать готовый экран.

## Практические рекомендации

Для хорошей работы на реальных телевизорах:

- не используйте изображения намного больше нужного разрешения;
- подготавливайте видео в разумном размере;
- не запускайте несколько тяжёлых видео одновременно без необходимости;
- используйте простые анимации для постоянно движущихся элементов;
- проверяйте сцену на самом слабом телевизоре из используемых моделей;
- не уменьшайте интервалы резервной сетевой проверки без причины.

## Как проект защищает эти правила

Автоматические проверки проекта должны обнаруживать возврат проблем, которые уже были устранены.

В частности проверяется, что:

- старое частое обновление экрана не возвращается;
- неизменившееся меню не создаётся заново;
- изменение меню не пересоздаёт неизменившееся видео;
- неудачная загрузка обязательного фона не уничтожает предыдущую рабочую версию;
- видео не копируется целиком в JavaScript ради обработки сетевых запросов;
- скрытые анимации и видео можно приостановить;
- постоянный цикл обновления кадров не используется там, где достаточно обычных событий браузера.

## Проверка при разработке

Перед добавлением новой функции полезно задать простой вопрос:

> Что эта функция будет делать на телевизоре в течение часа, если пользователь ничего не меняет?

Если ответ — постоянные запросы, повторная отрисовка или непрерывные вычисления без видимой причины, решение нужно пересмотреть.
