# MIRA-TV Player новой архитектуры

## Роль Player

Player не является редактором и не должен содержать бизнес-логику конструктора. Его задача — надёжно и экономно показывать назначенную runtime-сцену.

## Общий поток

```text
Scene / Catalog / Location
          ↓
     Scene Compiler
          ↓
    Runtime Snapshot
          ↓ HTTPS
      TV Player
```

WebSocket сообщает только о факте изменения. После уведомления Player получает актуальное состояние по HTTPS.

## Один Renderer

Player и Preview должны использовать общий Scene Renderer. Если один и тот же Scene Snapshot выглядит по-разному в редакторе и на TV, это считается архитектурным дефектом.

## Viewport

Для одного TV Player отображает весь Canvas. Для горизонтальной группы — только свою область глобального Canvas.

Player не изменяет координаты элементов и не создаёт отдельную сцену для каждого TV.

## Несколько TV

Все TV группы используют одну временную шкалу. Master TV отсутствует.

Каждый Player получает:

- идентификатор группы;
- Slot/viewport;
- версию сцены;
- общий timeline epoch или эквивалентный источник времени.

Это позволяет синхронно переключать слайды и анимацию.

## Last Known Good

Новая версия считается рабочей только после того, как Player подготовил обязательные данные и ресурсы.

До этого предыдущая рабочая версия остаётся доступной. Сбой сети, недоступное медиа или неудачное обновление не должны превращать рабочий телевизор в пустой экран.

## Offline

Player локально хранит минимально необходимое:

- последний рабочий Runtime Snapshot;
- необходимые Asset;
- служебные данные версии;
- ограниченный журнал диагностики.

После восстановления связи выполняется сверка с сервером.

## Delta-обновления

Если изменился только один источник данных, Player не должен полностью пересоздавать всю сцену.

Например обновление погоды не должно перезапускать неизменившееся видео, а изменение таблицы не должно пересоздавать логотип.

## Видео

Видео воспроизводится нативным механизмом браузера. Невидимые видео приостанавливаются. Player не копирует весь файл в память JavaScript для ручного декодирования.

## Диагностика

Player должен уметь сообщить серверу:

- активную версию сцены;
- текущий слайд;
- загрузочные и render-ошибки;
- состояние обязательных Asset;
- состояние синхронизации времени;
- heartbeat.

Журнал ограничен и не растёт бесконечно.

## Нагрузка

Если сцена статична и ничего не меняется, Player должен почти ничего не делать кроме минимального служебного обмена. Никаких постоянных циклов перерисовки без визуальной необходимости.
