# MIRA Render Agent

MIRA Render Agent — локальный компонент на компьютере администратора, который подготавливает финальное видео сцены перед публикацией на телевизоры.

## Зачем он нужен

Реальные тесты Android TV показали, что даже простые SVG/CSS-эффекты вроде glow, blur, drop-shadow и постоянно работающего motion loop могут создавать нагрузку, несоизмеримую с визуальной сложностью эффекта. При этом рабочий сервер MIRA-TV может быть очень маломощным и не должен тратить CPU/RAM на видеокодирование.

Поэтому тяжёлая подготовка переносится на компьютер администратора в момент публикации, а телевизор получает уже готовый H.264 MP4 и в основном занимается аппаратным декодированием.

## Утверждённая схема

```text
Scene Editor
    ↓
Опубликовать
    ↓
MIRA Render Agent на ПК администратора
    ↓
тот же SceneRenderer в каноническом разрешении
    ↓
FFmpeg / аппаратный encoder при наличии
    ↓
H.264 MP4
    ↓
MIRA-TV VPS
    ↓
Content Addressed Asset Store
    ↓
TV Local-first cache
    ↓
<video loop> + Live Weather Overlay
```

## Что запекается в видео

В итоговый ролик входят все элементы, которые не требуют данных реального времени:

- фон;
- таблица меню;
- цены;
- текстовые элементы;
- логотипы и изображения;
- видео внутри сцены;
- «Акция»;
- «Акционная строка»;
- декоративные эффекты;
- анимации сцены.

## Что остаётся живым

Погода не входит в итоговый MP4.

На телевизоре она остаётся существующим live-элементом и накладывается поверх видео в той же геометрии, которая задана Scene Editor.

В дальнейшем к live overlays могут добавляться только элементы, которым действительно нужны оперативные данные. Это не должно превращаться во второй полноценный renderer сцены.

## Единый renderer

Render Agent не должен иметь независимую реализацию меню.

Он обязан использовать тот же канонический SceneRenderer и те же данные сцены, что Preview и TV fallback. Отличается только способ доставки результата:

- Preview показывает SceneRenderer напрямую;
- Render Agent запускает SceneRenderer в полном разрешении и записывает результат;
- TV в основном режиме воспроизводит полученный MP4;
- если MP4 недоступен, TV временно использует существующий live renderer.

## Публикация

Сохранение и публикация — разные операции.

Обычное сохранение редактирует данные и не запускает видеорендер.

При публикации:

1. сервер формирует immutable render package и его SHA-256 input hash;
2. Render Agent получает package;
3. Agent проверяет версию renderer/protocol;
4. Agent создаёт H.264 MP4;
5. Agent загружает MP4 вместе с input hash и render revision;
6. сервер принимает файл только если исходные данные экрана всё ещё соответствуют package;
7. MP4 помещается в Content Addressed Asset Store;
8. сервер сообщает TV о новой версии;
9. TV скачивает видео в STAGING;
10. после успешной подготовки версия становится ACTIVE, предыдущая остаётся PREVIOUS.

Если во время рендера меню снова изменилось, устаревший MP4 не активируется.

## Кодек первой версии

Базовый профиль:

- контейнер: MP4;
- видео: H.264/AVC;
- pixel format: yuv420p;
- без аудио, если звук явно не поддержан сценой;
- размер равен разрешению экрана;
- целевая частота: 25 FPS;
- бесшовный loop.

H.264 выбран как наиболее совместимый базовый вариант для Android TV.

## Нагрузка

VPS не запускает Chromium и FFmpeg для рендера сцены.

Его обязанности:

- выдать render package;
- проверить upload;
- сохранить готовый asset;
- хранить привязку экрана к актуальному video asset;
- уведомить TV;
- удалить неиспользуемые assets после grace period.

Render Agent выполняет тяжёлую работу только при публикации.

TV выполняет тяжёлую работу только при первоначальной загрузке файла; во время длительного показа основной режим — video decode + live weather.

## Дедупликация

Render package имеет стабильный input hash.

Одинаковый package не должен рендериться повторно. Если подходящий MP4 уже есть в Asset Store, сервер может переиспользовать его для другого экрана с тем же render hash.

## Надёжность

До полной готовности новой версии:

- старый ACTIVE остаётся рабочим;
- новый MP4 не заменяет старый частично;
- отсутствие Render Agent не делает экран пустым;
- ошибка Agent не блокирует редактирование;
- TV может использовать live-render fallback;
- погода работает независимо от baked video.

## Менеджер

Роль менеджера не воспроизводит MP4 и не запускает полноценный renderer для каждой карточки.

Менеджеру достаточно актуального JPEG/WebP snapshot TV Player, полученного по запросу при загрузке/обновлении страницы. Fullscreen может использовать тот же сохранённый snapshot.

## Этапы внедрения

1. серверный Render Package API и хранение baked-scene asset;
2. Player Video Mode + live weather + Local-first;
3. MIRA Render Agent для Windows;
4. интеграция кнопки «Опубликовать» и статуса рендера;
5. сравнение Editor → Preview → encoded MP4 → TV;
6. Android TV benchmark;
7. после подтверждения — уменьшение роли старого непрерывного motion runtime.


## Ограничение pilot-версии

Первая реализация Video Mode запекает основную сцену и стандартные анимации, но не активный `scene_playlist`. У playlist пока нет deterministic seek для точного покадрового рендера.

Если playlist включён и содержит активные сцены, сервер помечает Render Package как `bake_supported=false`, а TV продолжает использовать существующий live renderer. Это безопасный fallback, а не удаление функции.

После подтверждения базового Video Mode на реальном Android TV для playlist будет добавлен отдельный deterministic timeline.
