# План развития MIRA-TV

Этот документ описывает общие направления развития проекта. Он не является обещанием точных сроков выпуска функций.

## Версия 1.0.0

Первая версия новой самостоятельной линии MIRA-TV должна дать понятную и устойчивую основу для дальнейшего развития.

Основные цели версии 1.0.0:

- единое название MIRA-TV во всём проекте;
- простая установка на Ubuntu;
- запуск всей серверной части одним Docker Compose проектом;
- PostgreSQL для хранения данных;
- удобная панель управления;
- каталог товаров;
- торговые точки и отдельные экраны;
- подключение телевизоров по QR-коду или короткому коду;
- показ меню непосредственно в браузере телевизора;
- продолжение показа последнего рабочего меню при временной потере связи;
- автоматическое получение изменений после восстановления соединения;
- поддержка изображений, видео и анимации;
- минимальная лишняя нагрузка на телевизор;
- понятная документация для установки и повседневной работы.

## После версии 1.0.0

Дальнейшие версии могут расширять возможности проекта в нескольких направлениях.

### Удобство управления

- улучшение массовой работы с экранами и торговыми точками;
- дополнительные инструменты для каталога;
- более удобное копирование и перенос настроек;
- улучшение диагностики состояния телевизоров.

### Оформление экранов

- новые варианты сцен и переходов;
- дополнительные типы медиаконтента;
- расширение возможностей редактора;
- более гибкое управление временными сценами.

### Надёжность

- дополнительные проверки восстановления после сбоев;
- улучшение диагностики проблем сети;
- более удобные резервные копии и восстановление;
- дополнительные проверки обновления приложения.

### Производительность

Новые визуальные возможности не должны ухудшать работу обычного статического меню.

Перед добавлением тяжёлой функции необходимо проверять её на реальном телевизоре и оценивать:

- загрузку процессора;
- использование памяти;
- сетевой трафик;
- плавность видео и анимации;
- поведение при длительной работе.

## Основной принцип развития

Новая функция считается полезной только если она решает реальную задачу и не делает систему заметно сложнее или тяжелее без необходимости.

Особенно это относится к коду, который постоянно работает на телевизоре.
