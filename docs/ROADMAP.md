# TV Menu 2.0 — план развития

## Утверждённый принцип отображения и сцен

MIRA-TV остаётся системой постоянно доступного меню, но экран больше не считается только одной непрерывно анимируемой таблицей. Базовая модель экрана — **Scene Playlist**:

- `Menu Scene` — основная постоянная сцена меню;
- `Promo Scene` — кратковременная акция;
- `Content Scene` — изображение, видео, текст или другой контент;
- `Object Story Scene` — короткая история Object+/Actor;
- сцена может быть overlay поверх меню или временно занимать весь экран;
- после временной сцены player гарантированно возвращается к базовой `Menu Scene`.

Обычное меню не должно расходовать ресурсы пропорционально числу строк. Статичное содержимое меню рендерится как одна **Flat Menu Surface**, а всё движущееся существует как небольшое число независимых scene layers и исполняется GPU/compositor-friendly renderer.

Целевой принцип:

```text
Static content  → Flat TV Renderer
Dynamic content → GPU Scene Engine / Layer Composer
Sequence        → Scene Playlist / Master Timeline
```

Количество строк меню не должно определять постоянную стоимость анимации. Новые эффекты не имеют права возвращать архитектуру к покадровому изменению десятков DOM/SVG-узлов.

## Live Player — браузерный вывод меню

Запланировать второй полноценный канал доставки наряду с файловой публикацией:

```text
TV MENU CORE
├── File Publish
│   ├── JPEG fallback
│   └── MP4 при необходимости
└── Live Player
    ├── Browser/Kiosk
    ├── Motion Engine
    ├── realtime updates
    └── player health
```

### Требования

- каждый монитор получает стабильный player URL;
- браузер в kiosk mode показывает тот же canonical screen scene, что редактор;
- публикация изменения может обновлять экран без полной перезагрузки страницы;
- WebSocket используется для realtime-команд и состояния;
- серверная временная шкала является источником времени для анимации;
- player регулярно отправляет heartbeat: online/offline, FPS, version, last sync, current scene;
- при кратком разрыве сети последнее валидное меню продолжает работать локально;
- JPEG остаётся аварийным fallback и независимым каналом публикации.

## Character Story Engine — сюжетная анимация персонажей

После появления browser/live renderer реализовать отдельный слой **Character Story Animation** поверх постоянного меню. Это не обычный motion preset и не переход между экранами: меню остаётся полностью открытым, а персонаж периодически запускает короткую фирменную историю.

Первый референсный персонаж — **рыбка из бокала**. Базовая история:

```text
рыбка находится в бокале
        ↓
оживает и выплывает
        ↓
плавает по безопасной траектории поверх/между элементами меню
        ↓
сверху появляется крючок
        ↓
рыбку подхватывают и тянут вверх
        ↓
у верхней границы она срывается
        ↓
возвращается по траектории обратно в бокал
        ↓
переход в спокойное состояние
```

### Архитектура

```text
Canonical Menu Scene
        +
Ambient Motion Engine
        +
Character Story Engine
        ↓
Browser Live Player
```

Story Engine должен работать как независимый событийный слой и не менять содержимое/геометрию самого меню.

### Сущности

- `CharacterAsset` — графика/спрайт/SVG персонажа и вспомогательных объектов;
- `CharacterAnchor` — исходная и конечная точка персонажа на конкретном экране, например положение рыбки в бокале;
- `StoryPreset` — готовая история;
- `StoryTimeline` — последовательность фаз и событий;
- `MotionPath` — траектория движения по координатам canonical scene;
- `StoryProp` — крючок, пузырьки, сеть и другие объекты истории;
- `LayerTrack` — порядок отображения перед/за таблицей и декоративными слоями;
- `SafeZone / ExclusionZone` — области, в которых персонаж не должен надолго перекрывать цены, названия и другие критичные элементы.

### Требования к поведению

- история запускается как редкое событие поверх спокойного ambient motion, а не непрерывно;
- задаётся интервал запуска и допустимая случайность внутри интервала;
- пользователь может включать одну историю, фиксированный набор или случайную ротацию историй;
- персонаж всегда имеет гарантированную точку возврата в исходное состояние;
- траектории учитывают реальные размеры/геометрию выбранного монитора;
- критичные зоны меню автоматически учитываются как зоны ограничения движения/перекрытия;
- story timeline поддерживает pause/resume/seek и в будущем синхронизацию по server clock;
- сложные сцены должны использовать compositor-friendly SVG/Canvas/Web Animations API и не снижать читаемость меню;
- при `prefers-reduced-motion` и аварийном fallback сюжетные сцены не запускаются;
- для каждого сюжета задаются длительность, частота, интенсивность, слой и допустимые зоны движения;
- Story Engine проектируется так, чтобы в будущем один персонаж мог переходить между viewport нескольких экранов одной `ScreenGroup`.

### Стартовый Story Pack для рыбки

1. **Короткое плавание** — рыбка выплывает, делает спокойный круг и возвращается в бокал.
2. **Исследование меню** — проходит по нескольким свободным зонам экрана и ненадолго задерживается возле акцентных разделов.
3. **Пузырёк** — рыбка преследует пузырёк, тот лопается, после чего она возвращается.
4. **Крючок** — рыбку ловят, поднимают вверх, она срывается и уплывает обратно в бокал.
5. **Побег от крючка** — крючок появляется раньше, рыбка уходит от него и прячется обратно.
6. **Золотая волна** — рыбка движется вслед за световым проходом Motion Engine.
7. **Пивная пена** — короткое появление/нырок через зону бокала и пены.
8. **Промо-маршрут** — рыбка мягко привлекает внимание к заданной позиции/разделу без перекрытия цены.
9. **Сеть** — попытка поймать рыбку сетью и короткий побег.
10. **Свободное плавание** — несколько безопасных маршрутов выбираются случайно, после чего персонаж возвращается к anchor.

### Редактор

В Motion Studio предусмотреть отдельный режим **«Сюжеты / Персонажи»**:

- выбор персонажа;
- выбор StoryPreset;
- реальный экран в мини-плеере;
- визуальное задание anchor и маршрута;
- настройка safe/exclusion zones;
- частота запуска;
- случайная ротация историй;
- длительность и интенсивность;
- слой отображения;
- ручной запуск истории для предпросмотра;
- timeline с фазами истории и scrubbing.

Первая версия не должна становиться полноценным сложным видеоредактором: основной сценарий — готовые профессиональные StoryPreset с возможностью безопасно настроить маршрут, частоту и интенсивность.

## Синхронизированные группы экранов

После Live Player реализовать сущность `ScreenGroup` для нескольких физических телевизоров, работающих как единая сцена.

Пример:

```text
Location
└── ScreenGroup «Бар»
    ├── Screen 1
    ├── Screen 2
    └── Screen 3
```

Для трёх экранов 1920×1080 редактор группы получает виртуальный холст 5760×1080. Каждый player отображает только собственный viewport общей сцены.

### Master Timeline

```text
Group Motion Studio
        ↓
Master Timeline / Server Clock
        ↓
 ┌──────┼──────┐
 ↓      ↓      ↓
TV 1   TV 2   TV 3
```

Требования:

- одна master timeline для всей группы;
- одинаковая позиция цикла определяется серверным временем, а не моментом открытия browser tab;
- поздно подключившийся player сразу переходит на текущую позицию сцены;
- периодическая оценка clock offset и drift correction;
- состояние синхронизации отображается в панели: online, FPS, clock offset, drift;
- переходящие между экранами объекты рассчитываются в координатах общего виртуального холста;
- individual tracks позволяют при необходимости анимировать только конкретный экран;
- отдельная библиотека group-motion presets: wave, panorama, domino, ripple, cross-screen slide, center pulse, promo journey и другие;
- Character Story Engine в group mode использует ту же master timeline и может переносить персонажа между экранами без перезапуска истории.

## Порядок реализации

Утверждённый порядок развития после v1.8.2:

1. **Flat TV Renderer** — статичное меню становится одной canvas/texture surface; DOM/SVG renderer остаётся редакторским и compatibility renderer до завершения переноса motion-слоёв.
2. **GPU Scene Engine / Layer Composer** — Brand, Object+, promo, transitions и FX становятся независимыми compositor/GPU layers; постоянная стоимость сцены должна быть близка к O(1) относительно числа строк меню.
3. **Scene Playlist** — `Menu Scene`, `Promo Scene`, `Content Scene`, overlay/fullscreen режимы, длительность, переходы и гарантированный возврат к меню.
4. **Object+ Actor / Story Engine** — actor states `enter / idle / action / focus / exit`, StoryPreset, StoryTimeline, MotionPath, props и safe zones.
5. **Screen Asset Cache** — локальный manifest и cache всех menu surfaces, изображений, видео, Object+ assets, шрифтов и scene definitions; offline playback без постоянной сети.
6. **Расписания** — смена Menu Scene и запуск Promo/Content Scene по времени, дням недели и периодам.
7. **POS/Catalog adapters** — iiko, R_keeper, QuickResto и другие источники обновляют canonical MIRA Catalog, а не экран напрямую.
8. **Widget Layer API** — Clock, Weather, QR, Timer, Queue, Exchange Rate, Custom API и другие widgets как обычные scene nodes.
9. После стабилизации single-screen scene runtime — `ScreenGroup`, общий виртуальный canvas, server clock, drift correction и cross-screen Object Story.

### Обязательные инварианты

- один canonical menu model используется редактором и всеми TV renderers;
- Flat Menu Surface не содержит долговременной индивидуальной анимации строк;
- динамика живёт в отдельных layers с явным ownership;
- `Menu`, `Brand`, `Actor/Object+`, `Promo`, `Content`, `Announcement`, `FX`, `Widget` являются семантическими сущностями, а не безымянными canvas-объектами;
- Scene Playlist не превращает MIRA-TV в общий графический редактор: ресторанная доменная модель остаётся первичной;
- TV Player должен продолжать показ последнего валидного состояния при потере сети;
- существующий JPEG/SFTP publish остаётся независимым fallback;
- новые runtime-механизмы должны иметь измеряемый performance budget и не зависеть от количества строк меню линейно.


## GPU Scene Layer Composer — реализован

- TV Player использует Flat Menu Surface даже при включённом animation profile;
- введён стабильный semantic layer stack: `menu / fx / content / entity / brand / announcement`;
- базовый menu motion компилируется в один coarse compositor effect;
- row-by-row WASM runtime удалён из TV Player и его offline shell;
- Motion Studio сохраняет legacy motion capability до отдельной миграции preview;
- следующий этап: `Scene Playlist` contract + `PromoScene / ContentScene`, затем Actor lifecycle для Object+.
