# Prototype: новый конструктор сцен

Ветка `prototype` используется для отработки нового пользовательского потока MIRA-TV без изменения стабильной модели данных `main`.

## Цель первого прототипа

Проверить руками основной UX:

1. открыть библиотеку сцен;
2. создать сцену отдельно от торговой точки;
3. выбрать 1–4 телевизора в горизонтальном ряду;
4. собрать несколько слайдов;
5. добавить на слайд таблицу, текст, изображение, логотип, видео, погоду, часы и фигуру;
6. перемещать и изменять размер элементов;
7. настраивать базовые визуальные свойства, эффекты и анимацию;
8. сохранить сцену как шаблон и снова открыть её из библиотеки.

## Почему пока используется localStorage

На стадии UX-прототипа сцены намеренно не записываются в PostgreSQL. Это позволяет несколько раз менять структуру Scene Schema без миграций рабочих данных.

После утверждения UX структура будет перенесена в серверный слой с нормальной БД, API, медиатекой и Player runtime.

localStorage не является целевым хранилищем продукта.

## Что не меняется

Существующие `screens`, `screen-editor`, TV Player, каталог, плейлист и эксплуатационные данные продолжают работать отдельно. Прототип не переопределяет их контракты.

## Принципы, которые уже фиксируются

- дизайн сцены отделён от физического TV;
- одна сцена содержит несколько слайдов;
- элементы являются объектами свободного Canvas;
- несколько TV образуют только горизонтальную панораму;
- размер одного TV в прототипе — 1920×1080;
- Canvas равен `display_count × 1920` по ширине и `1080` по высоте;
- дальнейшая серверная реализация должна сохранить единый Scene Model для Preview и TV Player.
