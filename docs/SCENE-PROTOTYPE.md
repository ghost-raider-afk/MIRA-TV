# Статус ветки prototype

Ветка `prototype` используется только для новой архитектуры Scene Editor и не является релизной веткой.

Точка ответвления: стабильный `main` MIRA-TV 1.0.3.

## Реализовано сейчас

- раздел «Сцены»;
- библиотека сцен;
- отдельный `scene-editor`;
- несколько слайдов;
- Canvas на 1–6 Full HD TV в горизонтальном ряду;
- направляющие физических TV;
- элементы: таблица, текст, изображение, логотип, видео, погода, часы, фигура;
- drag и resize;
- X/Y/размер;
- слои;
- базовый цвет, opacity и текстовые параметры;
- тень и свечение;
- каркас Entrance/Loop/Exit;
- фон слайда;
- Preview;
- Scene сохраняется на сервере в PostgreSQL и доступна после входа с другого браузера/устройства;
- библиотека сцен получает только лёгкие summary-записи, а полный Scene Graph загружается только при открытии сцены;
- сохранение использует серверный счётчик `server_revision` и optimistic concurrency: устаревшая вкладка не может молча затереть более новую версию;
- autosave сериализует запросы: медленный ответ не заменяет правки, сделанные пользователем во время сохранения;
- уход со страницы при реально несохранённых изменениях защищён стандартным предупреждением браузера;
- autosave Draft не создаёт отдельную запись журнала событий на каждое изменение;
- Table Element подключён к реальному существующему API каталога `/api/catalog/products`;
- Table Element умеет показывать реальные названия, производителя, крепость, цвет и фильтрацию;
- пользователь может вручную задать произвольные объёмы напитка, например `0,33; 0,5; 1; 1,5`;
- цена для выбранного объёма в прототипе рассчитывается пропорционально от существующей базовой цены за 1 литр;
- старые по структуре Table Element получают новый `data_binding` и безопасные настройки таблицы при нормализации Scene.

## Текущее серверное хранение

На стадии прототипа используется минимальная таблица `scenes`:

- идентификатор Scene;
- имя;
- версия Scene Schema;
- полный Draft Scene JSON в `JSONB`;
- серверный счётчик revision для защиты от конфликтов редактирования;
- автор создания/последнего изменения;
- timestamps.

Это уже настоящее серверное хранилище, но ещё не финальная модель публикации.

`server_revision` — технический счётчик конкурентного редактирования Draft. Он **не является** будущей неизменяемой `Scene Revision`, которая будет использоваться для публикации, rollback и назначения на TV.

## Временные решения

Table Element сейчас использует существующий legacy API продукции как временный bridge. Это реальные данные, но ещё не финальная универсальная модель Catalog Service. Целевая архитектура остаётся описанной в `CATALOG.md`.

Weather и Media пока остаются демонстрационными объектами и ещё не используют реальный Weather Provider и Asset Store.

Сервер пока сохраняет весь Draft Scene одним JSONB-документом. На этапе UX это намеренно: структура Scene ещё развивается. После стабилизации authoring-контракта можно отделить immutable published revisions и необходимые индексы, не заставляя Editor выполнять множество мелких записей на каждое движение элемента.

## Не реализовано в новой архитектуре

- immutable Published Scene Revision;
- публикация/rollback Scene;
- медиатека;
- реальный Weather Provider;
- финальная универсальная Catalog Schema;
- ручные ценовые override для конкретной пары позиция+объём в новой модели;
- назначение Template торговой точке;
- новый Display Group UI;
- runtime Scene Compiler;
- новый Player Scene Renderer;
- синхронизация нескольких физических TV;
- расписание новой модели.

## Неприкосновенные принципы

- Scene не принадлежит физическому TV;
- несколько TV — только горизонтальный ряд;
- одна Scene может иметь несколько Slides;
- элементы редактируются на свободном Canvas;
- Preview и Player в финальной реализации используют один renderer;
- UI оптимизируется на минимальное количество действий и мгновенный визуальный отклик;
- тяжёлая работа и повторные записи не выполняются без необходимости;
- Draft не должен терять изменения из-за гонки autosave;
- AI не добавляется до завершения ручного конструктора.

## Следующий критический шаг

Следующий вертикальный срез — общий Scene Renderer и путь к TV Player. Пока Editor Preview и будущий Player не используют один renderer, прототип нельзя считать готовым к VPS-приёмке.
