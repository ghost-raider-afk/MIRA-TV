# Диагностика MIRA-TV

Сначала выясните, что именно недоступно: сервер, подключение TV, данные сцены или отображение в конкретном браузере. Не очищайте хранилище TV и не удаляйте Docker volumes в качестве первого шага.

## Начальная проверка сервера

~~~bash
cd /opt/MIRA-TV
sudo docker compose config --quiet
sudo docker compose ps
sudo docker compose logs --tail=200
sudo docker compose logs app --tail=200
sudo docker compose logs proxy --tail=200
sudo docker compose logs db --tail=200
~~~

Проверка readiness из контейнера:

~~~bash
sudo docker compose exec -T app node -e "fetch('http://127.0.0.1:8080/readyz').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"
~~~

Если `/readyz` не готов, выясните причину из логов app/DB прежде чем перезапускать компоненты.

## Сайт не открывается

Проверьте DNS, сетевые порты `80/443`, состояние Traefik и сертификата, домен в `.env` и healthcheck app. Снаружи PostgreSQL не нужен и не должен открываться.

Если недавно меняли `compose.yaml` или `.env`, выполните `docker compose config --quiet`. Не регенерируйте `POSTGRES_PASSWORD` и `SESSION_SECRET` без согласованной процедуры: это может нарушить работу базы и действующие сессии.

## Нет входа или не подключается TV

Для входа проверьте имя пользователя, пароль, временное ограничение попыток и системное время. При необходимости используйте `sudo mira-tv reset-admin-password`.

Для TV откройте `https://ваш-домен/player`. Код подключения краткосрочный; повторите получение кода, выберите верные точку и экран, проверьте сеть и время на устройстве.

## TV показывает старое меню

Сначала убедитесь, что нужный экран опубликован и TV привязан именно к нему. Проверьте доступность API, WebSocket и fallback polling. Последняя рабочая сцена при потере связи остаётся на экране **намеренно**, это штатное Local-first поведение.

После восстановления сервера Player должен сверить ревизии самостоятельно. Если этого не происходит, собирайте серверные и TV-логи, проверяйте сессию и ошибки загрузки новых assets; перезагрузка страницы не должна быть стандартным способом синхронизации.

## Пропала таблица или фон на старом Android

Если подключение есть, но меню частично или полностью невидимо, сначала проверьте рендеринг CSS/SVG в конкретном браузере. Старый системный WebView не обязательно означает, что сторонний браузер использует такой же движок.

Проверьте, что оболочка Player и CSS-файлы полностью загрузились и не повреждены в кэше. При сравнении современных и старых устройств используйте одну сцену и канонический renderer. Не решайте проблему раздельным рендерингом Preview/TV.

## Пустая сцена после обновления

Убедитесь, что сохранились ACTIVE/PREVIOUS и необходимые `/site-assets/`. Если новая версия не подготовлена, Player обязан сохранить предыдущий LKG. Не удаляйте кэш или Service Worker до выяснения причины: при недоступном сервере это уничтожит локальную рабочую копию.

Если приложение не запустилось после обновления, проверьте `/var/lib/mira-tv/last-update-failure.log` и результат автоматического отката. Если откат прервался, временную резервную копию нельзя удалять до восстановления.

## Не работает погода

Проверьте серверное получение и кэш weather, заданные провайдеры и их доступность из backend, часовой пояс города и правильность владения виджетом (preset utility slot либо generic weather конструктора). TV не выполняет прямые вызовы внешнего API.

## Недостаточно места

~~~bash
df -h
sudo docker system df
~~~

Не запускайте массовые операции удаления Docker/volumes вслепую. Сначала выясните состав данных и подготовьте внешнюю резервную копию.

## Что приложить к сообщению о проблеме

Версию из `package.json`/интерфейса, `docker compose ps`, релевантные строки app/proxy/DB/Player логов, модель телевизора, версию браузера и точные шаги воспроизведения. Удалите из отчёта пароли, `.env`, cookie, токены, ключи и персональные данные.
