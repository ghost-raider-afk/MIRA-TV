# Диагностика MIRA-TV

## Сначала определить линию

Перед поиском проблемы важно понять, где она возникла:

- стабильная `main` / опубликованный релиз;
- разработческая ветка `prototype`.

Они пока используют разные модели Scene.

## Сервер стабильной версии

Базовые безопасные команды:

```bash
cd /opt/MIRA-TV
sudo docker compose ps
sudo docker compose logs --tail=200
sudo docker compose logs app --tail=200
sudo docker compose logs db --tail=200
```

Не удаляйте Docker volumes и не меняйте пароль PostgreSQL в попытке «проверить», пока причина не установлена.

## Сайт не открывается

Проверить контейнеры, домен, DNS, порты 80/443, HTTPS proxy, `.env` и логи приложения.

## TV не подключается

Проверить доступность `/player`, системное время TV, срок действия кода подключения, выбранную торговую точку/экран и сетевой доступ к серверу.

## TV показывает старое состояние

При потере сети это нормальная работа Last Known Good. После восстановления связи Player должен свериться с сервером автоматически.

Если связь есть, проверить назначение Device, realtime connection, fallback polling и серверные логи.

## Медиа не загружается

Проверить формат, размер, свободное место, серверную content validation и наличие runtime-зависимостей внутри production Docker image. Наличие инструмента на машине разработчика не доказывает, что он есть внутри контейнера.

## Проблемы prototype Scene Editor

Текущий прототип хранит Scene в браузерном `localStorage`.

Следствия:

- сцена не синхронизируется между разными браузерами;
- очистка данных сайта удалит prototype-сцены;
- Scene пока не появляется на физическом TV через новый runtime;
- Table, Weather и Media в первом каркасе могут быть демонстрационными объектами, а не реальными server-bound widgets.

Это не баг production-модели, а временная граница текущего этапа.

## Проблема drag/resize

Если объект двигается с задержкой, сначала искать полную перерисовку Scene, тяжёлые вычисления или сохранение данных на каждом pointer move. Нельзя маскировать такую проблему debounce, не выяснив источник лишней работы.

## Preview отличается от TV

В финальной новой архитектуре это считается дефектом общего Renderer contract. Не исправлять различия отдельными CSS-костылями для Preview и Player. Нужно искать, почему один и тот же Scene Model проходит через разные правила рендера.

## Панорамные TV расходятся по времени

Не синхронизировать их цепочкой TV→TV и не назначать TV1 master-устройством. Проверять общий источник времени, timeline epoch, clock offset и drift correction каждого Player.

## Что приложить к багу

- ветка и точный SHA;
- версия MIRA-TV;
- шаги воспроизведения;
- браузер/модель TV;
- скриншот или видео проблемы UI;
- относящиеся строки журнала;
- `docker compose ps`, если проблема серверная.

Никогда не прикладывать `.env`, пароли, cookie, device tokens и другие секреты.
