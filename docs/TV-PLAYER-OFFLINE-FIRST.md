# MIRA-TV TV Player: offline-first

## Цель

Телевизор должен начинать показ максимально быстро и не зависеть от доступности сервера для продолжения уже подтверждённой трансляции.

## Локальное состояние

IndexedDB хранит только runtime-данные конкретного телевизора:

- Last Known Good snapshot;
- последнюю подтверждённую revision;
- hashes независимых слоёв;
- sync metadata;
- локальную очередь диагностических событий.

Это не копия PostgreSQL.

Cache Storage хранит shell Player и тяжёлые assets: CSS, JS, изображения и видео.

## Запуск

1. Player открывает локальное durable state.
2. Если Last Known Good найден, он применяется немедленно.
3. Статические слои рендерятся только один раз для найденной revision.
4. Player параллельно пытается восстановить WebSocket/HTTPS.
5. Отсутствие сети не останавливает уже работающий показ.

## Last Known Good

Новая revision не становится Last Known Good сразу после получения JSON.

Последовательность:

1. получить delta/snapshot;
2. загрузить необходимые изменившиеся assets;
3. проверить критические данные;
4. применить изменившиеся слои;
5. подтвердить успешный runtime;
6. атомарно сохранить новую revision как Last Known Good.

При ошибке новая revision считается неуспешной, а последняя подтверждённая продолжает использоваться.

## Локальный журнал

Журнал append-only и содержит `boot_id` + монотонный `seq`. Он ограничен одновременно количеством записей и размером из `.env`.

При переполнении удаляются менее важные старые события; потеря части журнала сама фиксируется отдельным событием.

После восстановления связи Player отправляет события пакетами. Сервер подтверждает последний принятый sequence, после чего подтверждённые локальные записи можно удалить.

## Экономия ресурсов

В offline режиме запрещены агрессивные циклы reconnect. Используется exponential backoff с jitter. Невидимые анимации и media должны быть приостановлены, если они не участвуют в текущей сцене.
