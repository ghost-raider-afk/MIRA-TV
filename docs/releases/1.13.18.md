# MIRA-TV 1.13.18

Hotfix устойчивости погодного runtime после релиза 1.13.17.

## Исправлено

- Scene Editor больше не оставляет элемент «Погода» пустым после временного сбоя `/api/weather/preview` или внешнего погодного провайдера.
- Preview сохраняет последний корректный погодный snapshot в отдельном last-known-good кеше `mira-tv.weather.preview.last.v1`.
- При временной ошибке Preview повторяет запрос примерно через 1500 мс, а не оставляет виджет пустым до следующего длинного интервала.
- TV-cache и Preview-cache разделены.
- Серверный weather service при временной недоступности провайдера может вернуть последний успешно полученный snapshot даже после истечения штатного TTL.

## Архитектурный принцип

Исправление выполнено в lifecycle погодного snapshot/cache/retry. Контейнер и CSS погодного элемента не используются для маскировки ошибки. Preview и реальный TV остаются на общей canonical weather runtime-механике.

## Регрессии

- Unit test проверяет stale server snapshot fallback.
- Browser test принудительно возвращает `503` на первый `/api/weather/preview` и проверяет восстановление погодного виджета последующим запросом.
- Player shell regression обновлена под offline shell v34.
