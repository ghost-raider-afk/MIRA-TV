# MIRA-TV 1.13.20

Hotfix погодного runtime после v1.13.19.

## Причина

Погодный runtime считал `navigator.onLine` обязательным условием для запроса. Для MIRA-TV это неверно: Preview и физический TV получают погоду через same-origin API собственного MIRA-TV сервера. На LAN/VPN и некоторых Android TV/браузерах ОС может сообщать `navigator.onLine=false`, хотя MIRA-TV сервер доступен. В таком состоянии предыдущий runtime не выполнял запрос вообще, поэтому контейнер погоды существовал, а содержимое оставалось пустым.

## Исправлено

- Удалена зависимость weather schedule/refresh от `navigator.onLine`.
- Удалены browser `online/offline` listeners, отменявшие погодный таймер.
- Preview и TV продолжают использовать один `PlayerWeatherRuntime`.
- Существующие Preview LKG cache, retry и server stale fallback сохранены.
- Player build: `1.13.20`.
- Offline Player shell: `v36`.

## Регрессия

Browser-тест принудительно устанавливает `navigator.onLine=false`, оставляет same-origin `/api/weather/preview` доступным и проверяет фактическое появление «Комсомольск-на-Амуре» и температуры в Scene Editor.
