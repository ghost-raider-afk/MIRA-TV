# MIRA-TV 1.14.0

Серверная погодная подсистема с постоянным хранением и автоматическим резервированием бесплатных источников.

## Архитектура

Погодные данные больше не зависят от успешного обращения к одному внешнему сервису во время запроса Preview или TV Player.

Цепочка источников:

1. MET Norway — основной бесплатный provider.
2. Open-Meteo — резервный provider.
3. PostgreSQL last-known-good snapshot — используется при недоступности внешних источников.
4. Локальный TV LKG — дополнительная защита при недоступности самого сервера MIRA-TV.

Preview, TV Player и manager-view используют один общий WeatherService и один формат snapshot.

## Изменено

- Добавлен серверный Weather Collector.
- Погодные snapshots сохраняются в PostgreSQL и переживают рестарт приложения.
- Один город, используемый несколькими экранами, обновляется одним внешним запросом.
- Для общего города учитывается минимальный настроенный refresh_minutes среди использующих его экранов.
- При ошибке MET Norway выполняется автоматический fallback на Open-Meteo.
- Ошибка одного provider не очищает уже сохранённые данные.
- При недоступности всех внешних источников UI продолжает получать последний успешный snapshot с признаком stale.
- Часовой пояс выбранного города остаётся authoritative и применяется при нормализации времени прогноза.
- В журнале администратора добавлена категория «Погода».
- Смена состояния provider записывается один раз: отказ, восстановление или полный отказ погодной цепочки. Повторяющиеся одинаковые timeout не создают поток событий.
- Настройки weather-element по-прежнему принадлежат scene_json; отдельное хранилище настроек погоды не возвращено.
- Добавлены regression-тесты на failover, persistent LKG, restart, timezone, дедупликацию городов и интервалы обновления.
- Player build: 1.14.0.
- Offline Player shell: v38.

## Совместимость

Существующие сцены, weather-elements, API TV Player, Docker-конфигурация и сохранённые настройки экранов не требуют ручной миграции. Новые таблицы PostgreSQL создаются штатной миграцией 027.
