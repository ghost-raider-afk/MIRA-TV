# MIRA-TV 1.18.12

Production recovery release for TVs that stayed on a stale cached Player despite receiving current server state.

- «Применить на ТВ» is now an acknowledged soft re-provision of the selected TV, not a blind page reload.
- The existing device binding, device key, session and Local-first LKG are preserved; no QR code or repeated TV registration is required.
- A compatible `context.changed` command first lets older Player builds reconcile the new runtime/app version instead of trapping them in the previous cached renderer.
- The current Player then uses an uncached `/tv-recovery` trampoline to unregister the MIRA-TV Service Worker and delete only `mira-tv-player-shell-*` caches before returning to `/player`.
- The data/LKG cache remains available as a safety fallback while the refreshed Player loads current `screen`, `menu`, `scene`, `content_manifest` and `runtime` state.
- The server keeps the re-provision command across reconnects and considers Apply successful only after the refreshed Player acknowledges it and uploads a fresh TV snapshot.
- Scene Editor saves dirty state before re-provision and shows success only after the physical Player confirms completion; otherwise it reports that synchronization is still pending.
- Production post-merge smoke now covers the full soft re-provision path in addition to the existing Preview/Player apply smoke.
- No PostgreSQL schema, Docker volume, device binding, scene-data or renderer architecture changes.
