# MIRA-TV 1.18.13

Fullscreen and TV preview reliability release for physical Android TV Players.

- TV preview capture is delayed by 1.5 seconds after a render/apply event and rapid requests are coalesced, giving scene backgrounds and brand images time to settle before the diagnostic snapshot is published.
- The physical Player makes one automatic legacy-compatible Fullscreen API request when the rendered TV becomes active; no modern `navigationUI` options are required.
- If automatic fullscreen is rejected by the TV browser, Player shows a compact non-blocking «Нажмите OK для полноэкранного режима» hint once for about 5 seconds and then removes it.
- OK / Enter / DPAD Center can retry fullscreen from a real remote-control user gesture; arrow keys do not trigger fullscreen and Back remains available to leave fullscreen normally.
- Fullscreen ownership is consolidated in `player-fullscreen.js`; the main Player no longer contains a second direct Fullscreen API implementation.
- Fullscreen telemetry now includes the actual display mode, API capability and the latest request error. TV Network cards show a compact current `Fullscreen` / `Окно` / `Нет данных` status, while detailed telemetry and errors remain in TV management.
- Offline Player shell advances to v74 and Player/app version to 1.18.13 so the fullscreen and preview fixes reach already connected TVs through the existing update path.
- No PostgreSQL schema, Docker volume, device binding, scene-data or renderer architecture changes. No recurring fullscreen polling or animation loop is added.
