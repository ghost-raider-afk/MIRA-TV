# MIRA-TV 1.18.17

Local-first Player reliability and administrative TV unbinding.

## Reliable offline playback

- Keep the currently displayed TV scene visible when the server or internet becomes unavailable.
- Protect the previous complete Player shell from deletion during a failed upgrade; Service Worker activation does not force-navigate open TVs.
- Validate the required HTML, CSS and JavaScript response types before accepting a new shell.
- The boot watchdog no longer unregisters the working Service Worker or destroys shell caches; it attempts a bounded server recovery instead.
- Require successful asset staging before accepting a new LKG snapshot, including the theme's custom logo and decoration.
- Retry failed delta synchronization with bounded backoff even when WebSocket remains connected.
- Preserve the existing ACTIVE/PREVIOUS model, automatic WebSocket/delta updates, screen bindings, PostgreSQL data and Docker volumes.

## Administrator unbind

- An administrator-revoked session is distinguished from transient network failures and routine session rotation.
- Connected TVs receive an explicit revocation signal; disconnected TVs recognize their revoked session upon reconnecting.
- Only confirmed revocation clears local Player state/logs, shell and media caches, device identifiers and cached weather, then opens the pairing screen.
- Network outages, server errors and expired sessions do not destroy the last usable scene.

## Testing and compatibility

- Regression tests cover shell retention, critical theme media, revocation identity, WebSocket revocation and the absence of destructive recovery on ordinary errors.
- No 30-day long-duration test, extra runtime service, new dependency, database migration or renderer was introduced.
- Already connected TVs remain bound and do not require re-registration for this update.
- Player shell v78. Existing Player renderers and Preview/TV parity are preserved.
