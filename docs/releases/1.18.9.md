# MIRA-TV 1.18.9

## Что изменено

- Исправлена первопричина, из-за которой уже подключённый Android TV мог остаться на старом закэшированном Player renderer после обновления сервера. Offline Player shell обновлён до **v70** и при реальном обновлении один раз переводит уже открытый `/player` на активный shell без фонового reload-loop.
- Благодаря этому утверждённый стиль **«Читаемый · 2 колонки»** снова гарантированно доходит до ранее застрявших ТВ: визуальная колонка `1,5 л` в этом стиле отсутствует, как и в каноническом Preview/renderer.
- Исправлен snapshot ТВ в **«ТВ сети»**: захват кратко ждёт изображения, встраивает изображения и `background-image` всех дочерних слоёв сцены, а не только корневого stage.
- Неполный кадр с недоступным visual asset больше не заменяет Last Known Good snapshot; предыдущий рабочий кадр сохраняется до успешного нового захвата. Временная ошибка загрузки asset не кэшируется навсегда и повторяется при следующем event-driven capture.
- Кнопка **«Применить на ТВ»** теперь действительно является force-apply. Если Preview содержит несохранённые изменения, одним нажатием сначала выполняется штатное сохранение текущего состояния, затем сервер отправляет отдельный realtime `force_render`. TV Player один раз перезапускается на последнем сохранённом состоянии и после повторного подключения публикует новый snapshot. Если сцена уже сохранена, выполняется только force-apply без повторного сохранения.
- Обычные изменения по-прежнему используют лёгкий delta/WebSocket-путь. Однократный reload выполняется только по явному **«Применить на ТВ»**; фоновых reload/capture циклов не добавлено.
- Player build синхронизирован с **1.18.9**, Offline Player shell — **v70**. Local-first, ACTIVE/PREVIOUS, WebSocket + редкий fallback polling и event-driven preview сохранены.
- Release pipeline теперь имеет обязательный post-merge production smoke: после зелёного `check` на `main` поднимается production Compose, проверяется `/readyz` и критический Admin → TV → Preview/Player путь; GitHub Release публикуется только после успешного smoke.

Без изменений PostgreSQL schema, Docker volumes, привязки ТВ и исторических migrations.
